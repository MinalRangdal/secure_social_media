🔬 Cryptography Demo

Understanding how SHA-256 hashing protects social media content from unauthorized reuse and tampering

📚 What is This System?

CryptoGram is an academic demonstration of how cryptographic hashing can be used to:

  • Verify Content Integrity: Detect if an image has been modified or tampered with
  • Establish Ownership: Prove who originally uploaded specific content
  • Detect Unauthorized Reuse: Identify screenshots or re-uploads of original content
  • Prevent Repudiation: Users cannot deny posting specific content

⚠️ Important Disclaimer

This system does NOT prevent screenshots at the OS level. That is technically impossible for web applications. Instead, it provides cryptographic proof of content authenticity and detects tampering.

⚙️ How It Works

Step-by-Step Process:

1. USER UPLOADS IMAGE
↓
2. BACKEND READS IMAGE BYTES
↓
3. SHA-256 ALGORITHM PROCESSES BYTES
↓
4. GENERATES 64-CHARACTER HEXADECIMAL HASH
Example: a3f5b8c2d4e6f1a2b3c4d5e6f7a8b9c0...
↓
5. HASH STORED IN DATABASE (linked to user & image)
↓
6. IMAGE DISPLAYED NORMALLY IN FEED
↓
7. IF VERIFICATION REQUESTED:
- Recompute current image hash
- Compare with stored hash
- Match = ✅ Verified | Mismatch = ❌ Tampered

Why SHA-256?

  • Deterministic: Same input always produces same output
  • One-Way Function: Cannot reverse hash to get original image
  • Collision Resistant: Virtually impossible for two different images to have same hash
  • Avalanche Effect: Changing one pixel completely changes the hash
  • Fast Computation: Quick to generate and verify
  • Industry Standard: Used in Bitcoin, SSL, digital signatures

✅ What This System CAN Do

✓ Cryptographic Guarantees

  • Detect if an image has been modified (even by 1 pixel)
  • Prove original ownership with timestamp
  • Identify screenshots (different file = different hash)
  • Verify content integrity
  • Prevent users from denying they posted something
  • Mark unverified content visually (blur + warning)

❌ What This System CANNOT Do

✗ Technical Limitations

  • Cannot prevent screenshots (OS-level operation)
  • Cannot stop users from downloading images
  • Cannot prevent screen recording
  • Cannot stop someone from taking a photo of the screen
  • Cannot block image viewing

💡 Why Screenshots Can't Be Blocked

Screenshots are controlled by the operating system (Windows, macOS, Android, iOS), not web browsers. Web applications run in a sandboxed environment with limited system access. Only OS-level DRM (like Netflix on mobile apps) can prevent screenshots, and even that is not foolproof.

Our approach: Instead of trying to prevent the impossible, we focus on detection and verification using cryptography.

🎯 Real-World Scenario

Scenario: User Alice posts a photo

  1. Alice uploads photo.jpg
  2. System computes: hash_A = SHA256(photo.jpg)
  3. Hash stored: a3f5b8c2d4e6...
  4. Photo appears in feed with ✅ Verified badge

Scenario: User Bob tries to reuse Alice's photo

  1. Bob takes screenshot of Alice's photo
  2. Bob uploads screenshot as his own post
  3. System computes: hash_B = SHA256(screenshot.png)
  4. Result: hash_B ≠ hash_A
  5. System marks Bob's post as ⚠️ Unverified
  6. Original ownership remains with Alice

Why hashes differ:

  • Screenshot has different metadata
  • Different file format (JPG → PNG)
  • Screen compression artifacts
  • Pixel values may slightly differ
  • File structure is completely different

Result: Even if Bob's screenshot looks identical to human eyes, cryptography proves it's not the original.

🌍 Real-World Applications of SHA-256

1. Bitcoin & Blockchain

Every block in Bitcoin blockchain is identified by its SHA-256 hash. This ensures transaction integrity.

2. SSL/TLS Certificates

When you visit an HTTPS website, SHA-256 verifies the certificate hasn't been tampered with.

3. Digital Signatures

Email signatures, PDF signatures, and code signing all use SHA-256 to verify authenticity.

4. Git Version Control

Every commit in Git is identified by its SHA-1/SHA-256 hash, making it impossible to alter history.

5. File Integrity Monitoring

Antivirus software and security tools use hashing to detect if system files have been modified by malware.

6. Password Storage

Websites store hashed passwords (with salt) instead of plain text for security.

🎓 Viva Questions & Answers

Q1: Why can't you prevent screenshots?

A: Screenshots are OS-level operations controlled by Windows/macOS/mobile OS, not web browsers. Web applications run in a sandboxed environment with limited system access. Only native apps with DRM (like Netflix) can attempt to block screenshots, and even those can be circumvented.

Q2: What cryptographic guarantees does SHA-256 provide?

A:

  • Integrity: Any change produces different hash
  • Authenticity: Original uploader's hash proves ownership
  • Non-repudiation: Cannot deny uploading specific content
  • Collision resistance: Virtually impossible for two images to have same hash (probability: 1 in 2^256)

Q3: How does this protect content if screenshots are possible?

A: If someone screenshots and re-uploads, the hash will differ from the original. The system marks it as "unverified," proving they don't own the original content. This provides legal and ownership evidence even if the content can be copied visually.

Q4: What are the limitations?

A:

  • Cannot stop viewing/downloading
  • Cannot prevent screenshots
  • CAN prove tampering
  • CAN establish original ownership
  • CAN provide legal evidence

Q5: Why SHA-256 over MD5 or SHA-1?

A: MD5 and SHA-1 have known collision vulnerabilities. SHA-256 is currently considered cryptographically secure with no known practical attacks. It's the industry standard for security-critical applications.
